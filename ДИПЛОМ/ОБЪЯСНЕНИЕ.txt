2. КАК ВСЁ УСТРОЕНО (ПРОСТЫМИ СЛОВАМИ)
=====================================================================

Сайт состоит из трёх частей, как ресторан:

  БРАУЗЕР (клиент, React)  =  зал: гость смотрит меню и делает заказ
  СЕРВЕР (Express)         =  официант и повар: принимает заказ, проверяет, готовит
  БАЗА ДАННЫХ (PostgreSQL) =  склад: хранит всё, что нужно (пользователи, кружки, заявки)

Путь одного действия, например «записаться в кружок»:
  1) Участник заполняет форму на странице кружка (client/src/pages/ClubDetail.jsx).
  2) Браузер отправляет запрос POST /api/registrations на сервер (client/src/api.js).
  3) Сервер проверяет токен – кто ты и не заблокирован ли ты (server/src/middleware/auth.js).
  4) Сервер проверяет роль – записываться может только участник.
  5) Сервер проверяет данные формы и наличие свободных мест (server/src/routes/registrations.js).
  6) Если всё хорошо – сохраняет заявку в таблицу registrations со статусом «pending».
  7) Организатор видит заявку у себя и нажимает «Подтвердить» – статус меняется.

4. КАК ЗАПУСТИТЬ (КОРОТКО, ПОДРОБНО – В README.md)
=====================================================================

Нужно: Node.js 18+ и PostgreSQL 14+.

  1) Создать базу:        CREATE DATABASE kruzhki;
  2) В папке server:      npm install
                          скопировать .env.example в .env и вписать пароль от PostgreSQL
                          npm run db:init
                          npm run db:seed
                          npm start
  3) В папке client:      npm install
                          npm run dev
  4) Открыть http://localhost:5173

Тестовые входы:
  admin@kruzhki.local      / admin123
  organizer@kruzhki.local  / org12345
  user@kruzhki.local       / user1234

Если не запускается:
  – «ECONNREFUSED 5432»  → PostgreSQL не запущен или неверный порт.
  – «password authentication failed» → неверный пароль в DATABASE_URL в файле .env.
  – «Не задан JWT_SECRET» → не создан файл .env (скопируй из .env.example).
  – Сайт открылся, но данных нет → не запущен сервер (npm start) или не выполнен db:seed.

5. 8 ВЕЩЕЙ, КОТОРЫЕ НУЖНО ПОНИМАТЬ ДЛЯ ЗАЩИТЫ
=====================================================================

1) Роли. Четыре: гость, участник, организатор, админ. Роль хранится в таблице users.
   Администратором через форму регистрации стать нельзя – сервер превращает любую
   роль, кроме organizer, в participant.

2) JWT-токен. После входа сервер выдаёт «пропуск» (токен) на 7 дней. Браузер хранит
   его в localStorage и прикладывает к каждому запросу. Сервер проверяет подпись.

3) bcrypt. Пароль не хранится – хранится его необратимый «отпечаток» (хеш).
   Даже имея базу, пароль напрямую не прочитать.

4) Проверка прав на СЕРВЕРЕ. Компонент Protected на сайте только прячет страницы
   (для удобства). Настоящая защита – middleware auth/requireRole на сервере.
   Подделать кнопку в браузере можно, обойти проверку сервера – нет.

5) Чужие данные защищены в самом SQL. Например, организатор меняет кружок запросом
   «... WHERE id = ? AND organizer_id = <мой id>» – чужой кружок просто не найдётся.

6) Места в кружке. Свободно = capacity – число заявок в статусах pending и confirmed.
   При записи сервер открывает транзакцию и блокирует строку кружка (FOR UPDATE), чтобы
   два человека не заняли последнее место одновременно.

7) Защита от повторной заявки. Это правило в самой базе: уникальный индекс
   (club_id, user_id, participant_name) только для активных заявок. После отмены
   можно записаться снова.

8) SQL-инъекции. Все запросы с $1, $2 (параметры), а не склейкой строк, поэтому
   вредный текст из формы не превращается в SQL-команду.

6. ВОПРОСЫ, КОТОРЫЕ МОГУТ ЗАДАТЬ, И КРАТКИЕ ОТВЕТЫ
=====================================================================

В: Почему выбран React / Node / PostgreSQL?
О: Один язык (JavaScript) на всём проекте; PostgreSQL – надёжная реляционная база
   с транзакциями и ограничениями; Express – простой фреймворк для REST API.

В: Что такое REST API?
О: Набор адресов, по которым клиент обращается к серверу: GET – получить,
   POST – создать, PUT – изменить, PATCH – частично изменить, DELETE – удалить.
   Ответы приходят в формате JSON.

В: Как защищены пароли?
О: Хеш bcrypt с «солью». Пароль в открытом виде нигде не хранится.

В: Что будет, если заблокировать пользователя, пока он залогинен?
О: Сервер при каждом запросе заново читает пользователя из базы и видит блокировку –
   доступ закрывается сразу (это проверено тестом).

В: Что такое транзакция и зачем она при записи?
О: Группа операций, которая выполняется целиком или не выполняется вовсе. Нужна,
   чтобы подсчёт мест и создание заявки не «разъехались» при одновременных запросах.

В: Почему кружок не удаляется, а скрывается?
О: Чтобы не терять заявки и историю. Поле is_active = false убирает его из каталога.

В: Какие у проекта слабые места?
О: Токен в localStorage (в «боевом» проекте лучше HttpOnly-cookie); нет подтверждения
   email, нет ограничения частоты запросов, нет автотестов интерфейса, нет загрузки фото.
   Это описано в дипломной записке в разделе 3.4 и в заключении – так и отвечай.

В: Чем твой сайт отличается от Госуслуг/Навигатора?
О: Те привязаны к региональным программам и сертификатам; здесь простой каталог для
   любых организаторов – школ, студий, сообществ (см. таблицу 1 в дипломе).

В: Что бы ты добавил дальше?
О: Отзывы, избранное, фото, письма о смене статуса, карту, пагинацию, автотесты, хостинг с HTTPS.

10. ПОЧТА И WHATSAPP (НОВОЕ)
=====================================================================

ПОЧТА. Файл server/src/mailer.js. Когда родитель отправляет заявку, сервер (после
сохранения в базу) отправляет письмо ОРГАНИЗАТОРУ ЭТОГО КРУЖКА на email из его
аккаунта: «К вам записались: <ребёнок> → <кружок>» (ребёнок, год рождения, родитель,
телефон, комментарий, ссылка на раздел «Заявки»). Письмо уходит в фоне, чтобы сайт не
«подвисал». У демо-организаторов почта на «.local» (такой почты не существует), поэтому
для них используется запасной адрес NOTIFY_EMAIL из server/.env.
Родитель получает «заявка принята» и затем «подтверждена/отклонена» (если у него
настоящая почта); кнопка «Ответить» в этих письмах ведёт к организатору.
Сервис отправки – Gmail через пакет nodemailer, вход по ПАРОЛЮ ПРИЛОЖЕНИЯ
(как получить – в README.md). Сбой почты не ломает запись: ошибка только печатается
в терминале.

WHATSAPP. Файл client/src/config.js и components/WhatsAppButton.jsx. Ссылка
https://wa.me/НОМЕР?text=... открывает чат с номером владельца и подставляет текст.
Номер задаётся в client/.env (VITE_WHATSAPP_PHONE). Адрес web.whatsapp.com сам по себе
чат не открывает – это просто вход в WhatsApp Web, поэтому нужен именно номер.
Кнопки: плавающая зелёная справа внизу, «Спросить в WhatsApp» в карточке кружка
(с названием кружка в тексте) и ссылка в подвале.

ВАЖНО ПРО ЧЕСТНОСТЬ: письма я проверил в тестовом режиме (MAIL_MODE=console: письма
формируются правильно, адресаты определяются верно, «отправка» идёт в терминал). Реальную отправку через Gmail
из моей среды проверить нельзя – проверь у себя по README и убедись, что письмо
пришло. Это про «СМС»: настоящие СМС на телефон требуют платного сервиса, поэтому
используется почта.
