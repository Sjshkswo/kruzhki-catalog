# Веб-каталог кружков и секций с регистрацией участников

Сайт-каталог, где **родители находят кружки и секции** по возрасту ребёнка, категории и цене и **записывают ребёнка онлайн**. **Организаторы** публикуют свои кружки и подтверждают заявки, **администратор** проверяет организаторов и кружки и следит за порядком.

Роли: гость, родитель, организатор, администратор. Проблема, которую решает проект: информация о кружках разбросана по соцсетям, а запись идёт по телефону и теряется.

Стек: React (Vite) + Node.js/Express + PostgreSQL. Версия 1.1 (исправление бизнес-логики и безопасности по ТЗ 2.0).

## Что нужно установить

- Node.js 18+ (https://nodejs.org)
- PostgreSQL 14+ (https://www.postgresql.org/download/)

## Запуск

### 1. База данных
Создайте пустую базу (в pgAdmin или командой):

```
psql -U postgres -c "CREATE DATABASE kruzhki;"
```

### 2. Сервер
```
cd server
npm install
copy .env.example .env      (Linux/Mac: cp .env.example .env)
```
Откройте `server/.env` и впишите свой пароль от PostgreSQL в `DATABASE_URL` и любую длинную строку в `JWT_SECRET`. Затем:
```
npm run db:init     # применяет миграции (безопасно, ничего не удаляет)
npm run db:seed     # демо-данные (только в чистую базу)
npm start           # API на http://localhost:4000
```

### 3. Клиент (в новом терминале)
```
cd client
npm install
npm run dev         # сайт на http://localhost:5173
```

### 4. Вход
| Роль | Email | Пароль |
| --- | --- | --- |
| Администратор | admin@kruzhki.local | admin123 |
| Организатор | organizer@kruzhki.local | org12345 |
| Организатор | organizer2@kruzhki.local | org12345 |
| Родитель | user@kruzhki.local | user1234 |

Демо-пароли только для разработки. На публичном сервере создайте администратора с другим паролем.

## Как стать организатором

Новый пользователь регистрируется как **родитель**. В профиле он подаёт заявку «Стать организатором» (название организации, БИН/ИИН, телефон). Администратор одобряет её во вкладке «Организаторы» админ-панели. Кружок организатора попадает в каталог только после одобрения администратора.

## База данных и миграции

| Команда | Что делает |
| --- | --- |
| `npm run db:init` | Применяет единую миграцию `server/migrations/005_consolidated_schema.sql`. Безопасно: существующие пользователи, кружки и заявки сохраняются; старые схемы обновляются на месте. |
| `npm run db:reset` | **Стирает всю базу** и создаёт заново. Только для разработки: при `NODE_ENV=production` отказывается работать |
| `npm run db:seed` | Добавляет или обновляет демо-данные (не запускайте на рабочей базе без необходимости) |

## Секреты и безопасность репозитория

- Настоящие пароли хранятся **только** в `server/.env` (он закрыт в `.gitignore`).
- В `.env.example` значения оставляются пустыми. Если пароль случайно попал в репозиторий, его нужно **отозвать**, а не просто удалить из файла: он останется в истории Git.
- Для писем используется пароль приложения Gmail (не обычный пароль): https://myaccount.google.com/apppasswords

## Уведомления на почту (необязательно)

Организатору приходит письмо «Новая заявка в кружок X» со ссылкой на кабинет (персональных данных детей в письме нет). Родителю приходят письма «заявка принята», «подтверждена», «отклонена» или «отменена». Для организаторов с демо-почтой (`.local`) письма идут на `NOTIFY_EMAIL`.

В `server/.env` заполните `MAIL_USER` и `MAIL_PASS` (и при желании `NOTIFY_EMAIL`), затем перезапустите сервер. В терминале при заявке появится строка `[почта] ... отправлено`. Без настройки сайт работает, письма пропускаются. Для проверки без отправки добавьте `MAIL_MODE=console`.

## WhatsApp

В `client/.env` (копия `client/.env.example`) укажите номер цифрами с кодом страны, без плюса и пробелов: `VITE_WHATSAPP_PHONE=77001234567`. Перезапустите сайт. Кнопка внизу справа, кнопка в карточке кружка и ссылка в подвале будут открывать чат (`wa.me/номер`).

## Если сервер не запускается

В папке `server` выполните `npm run check`: команда проверит Node.js, файл `.env`, подключение к PostgreSQL, миграции и порт и подскажет, что исправить. Те же проверки выполняются при каждом `npm start`, и при проблеме сервер пишет причину в терминале.

| Сообщение | Что делать |
| --- | --- |
| Подключение к базе данных (ECONNREFUSED) | Запустите PostgreSQL (службы Windows → `postgresql-x64-…`) |
| Подключение к базе данных (28P01) | Неверный пароль в `DATABASE_URL` |
| Подключение к базе данных (3D000) | Не создана база `kruzhki` (pgAdmin → Databases → Create) |
| Миграции базы данных применены ✗ | `npm run db:init` |
| JWT_SECRET задан ✗ | Впишите любую длинную строку в `server/.env` |
| Порт 4000 уже занят | Сервер уже запущен в другом окне: закройте его (Ctrl+C) |

## Автоматическая проверка API

**Тесты меняют базу, запускайте только на тестовой!** При запущенном сервере:
```
cd server
npm run db:reset
npm run db:seed
npm test
```
Ожидаемый итог: «пройдено 37 из 37». После теста снова выполните `db:reset` и `db:seed`.

### Создание кружков администратором

Администратор может создать кружок из админ-панели кнопкой «+ Создать кружок».
Кружок, созданный администратором, сразу получает статус модерации `approved` и
публикуется в каталоге. Создание записывается в `admin_log` как `club_created`.
Организаторы продолжают создавать кружки через раздел «Мои кружки»; их новые
кружки проходят обычную модерацию.
